# 1. 統合ログ収集：まず何を調べるかを決める

利用者が「さっき保存に失敗した」と言ったら、時刻、サービス、処理が止まった箇所を知る必要があります。ログは処理中に発生した出来事の記録です。マイクロサービスでは複数のコンテナに分散するため、収集先をまとめると、一つずつコンテナを開かずに検索できます。

## 三種類の記録は別の問いに答える

| 記録 | 主に分かること | このプロジェクトの確認先 |
|---|---|---|
| 実行ログ | なぜエラーになったか、処理がどこまで進んだか | Dockerのログ。収集有効時はGrafanaからLokiを検索 |
| 操作ログ | 誰がどの業務操作を行い、どう終わったか | マイワークスペース → 運用監視 → 操作ログ |
| セキュリティ監査 | ログイン、拒否、セキュリティ設定変更 | システム管理の監査ログ、ログイン記録、認可記録 |

仕入先更新の失敗なら、実行ログで例外、操作ログで実行者と操作、ログイン記録で本人確認の経緯を調べます。相互に代用はできません。操作ログが空でも、リクエストがなかったとは限りません。

## 最初に覚える用語

**構造化ログ**は時刻、レベル、サービス、メッセージなどを項目に分けます。**収集器**は記録を運び、**ストレージ**は保存と検索を担当し、**検索画面**は結果を表示します。**traceId**は関連付けの手掛かりであり、ログイン資格情報でも、完全なトレースを保存した証拠でもありません。

実行ログの経路は、アプリ出力 → Dockerログ → Alloy → Loki → Grafanaです。アプリのCompose設定はECS JSONを既定にします。任意のAlloy、Loki、Grafanaが停止中でもコンテナログは残り得ますが、集中検索は利用できません。
