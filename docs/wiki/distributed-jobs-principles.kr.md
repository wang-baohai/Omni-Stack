# 1. 예약 작업의 기초: 시간이 되면 누가 일을 할까요?

매일 물을 마시라고 알려 주거나, 일정 간격으로 발송 대기 메시지를 큐에 넘기고 싶다고 생각해 보세요. 사람이 페이지를 켜 두고 계속 버튼을 누르는 대신, 할 일과 시간을 정해 프로그램이 실행하도록 하는 것이 예약 작업입니다.

시간을 정한다고 실패, 중복 실행, 권한 문제까지 해결되지는 않습니다. 이 장은 쉬운 개념부터 시작해 현재 사용하는 XXL-JOB의 내부 흐름을 살펴보고 실제 화면으로 사용법을 설명합니다. 처음부터 Java를 읽을 필요는 없습니다.

## 세 가지 질문을 나누기

| 질문 | 담당 | 비유 |
|---|---|---|
| 언제 시작할까요? | 스케줄링 센터 | 시간표를 가진 당직실 |
| 어느 서비스 인스턴스에 맡길까요? | 라우팅 정책과 실행기 등록 | 일할 수 있는 담당자에게 배정 |
| 무엇을 했고 성공했나요? | 실행기 안의 업무 처리기 | 실제 작업과 결과 보고 |

실행기는 별도의 독립 업무 시스템이 아닙니다. 이 프로젝트에서는 업무 서비스 안에서 실행되고, 기본 XXL-JOB Admin이 공통 관리 웹 화면을 제공합니다. 배정을 받았다고 업무가 끝난 것은 아니므로 실행 기록과 업무 결과까지 확인합니다.

## 분산이라는 말의 뜻

하나의 서비스를 여러 인스턴스로 운영할 수도 있고, 여러 서비스가 서로 다른 일을 할 수도 있습니다. 센터는 사용 가능한 실행기를 파악하고 정책에 따라 주소를 고릅니다. 중앙에서 관리하면 상태 확인과 복구가 쉬워집니다.

모든 작업이 자동으로 여러 조각으로 나뉜다는 뜻은 아닙니다. 일반 라우팅은 주소 하나만 고를 수 있고, 샤딩 브로드캐스트는 여러 주소에서 실행할 수 있습니다. 데이터 분할과 중복 방지는 업무 설계의 책임입니다.

## Cron은 시간표입니다

Cron은 초, 분, 시, 날짜 등의 위치로 실행 시간을 표현합니다. 먼저 화면의 주기 선택에서 매일 몇 시인지, 얼마나 자주인지 이해한 뒤 예상 실행 시간을 확인하세요. 여기서 쓰는 초 단위 표현식과 운영체제의 다섯 필드 표현식을 혼용하면 안 됩니다.

시간대, 처리 시간, 놓친 실행 시각에 대한 정책도 확인합니다. 10초마다 실행하는데 한 번에 1분이 걸린다면 대기, 후속 요청 버리기, 이전 실행 대체 같은 중복 요청 처리 정책이 필요합니다. 호출 횟수를 늘려도 처리기 자체가 빨라지지는 않습니다.

## 중복이 생기는 이유와 멱등성

업무는 끝났는데 성공을 보고하는 통신이 끊길 수 있습니다. 센터는 확인을 못 받았으므로 다시 배정하고, 같은 업무가 반복될 수 있습니다. 수동 실행과 예약 실행이 겹칠 수도 있습니다.

멱등성이란 같은 일을 다시 받아도 한 번만 생겨야 할 결과가 중복되지 않게 하는 것입니다. 안정적인 업무 식별자, 고유 제약, 적절한 트랜잭션 등을 사용합니다. 스케줄링 잠금, 재시도, 실행 주소 하나만 선택하는 설정이 업무 멱등성을 대신하지는 않습니다.

## 프로젝트의 두 가지 작업 계열

시스템 작업은 작업 로그 보관과 MQ 중계처럼 프로젝트에 포함된 유지보수 기능이며 권한 있는 관리자가 관리합니다. 개인 작업은 물 마시기 알림처럼 사용자가 내 워크스페이스에서 만들며, 현재 테넌트와 작성자에게 속합니다.

두 계열은 XXL-JOB를 공유하지만 진입점, 소유권 검사, 로그가 다릅니다. 기본 Admin에서 개인 작업을 바꿔 워크스페이스의 소유권 검사를 우회하지 마세요.
