# 1. 统一日志采集：先弄清楚在查什么

用户说“刚才保存失败了”，你需要知道发生时间、出错的服务，以及失败发生在哪个环节。日志就是程序在处理过程中留下的事件记录。微服务分散在多个容器里，统一采集把这些记录集中到同一个可检索入口，让排查不必逐个容器翻找。

## 三种记录，回答三个问题

| 记录 | 主要回答什么 | 当前去哪里查 |
|---|---|---|
| 运行日志 | 服务为什么报错、请求走到了哪里 | Docker 容器日志；启用采集后用 Grafana 查询 Loki |
| 操作日志 | 谁执行了哪项业务操作、结果怎样 | 工作台 → 运维监控 → 操作日志 |
| 安全审计 | 谁登录、被拒绝、改了哪些安全配置 | 系统管理中的审计日志、登录记录和授权记录 |

例如，修改供应商失败时，运行日志帮助找异常；操作日志帮助确认操作人和动作；登录记录只能解释身份进入系统的经过。它们不能互相替代，空的操作日志也不表示从未发生过请求。

## 先认识几个词

**结构化日志**把时间、等级、服务、消息等拆成字段，便于筛选。**采集器**负责搬运记录，**存储**负责保存与检索，**查询界面**负责展示。**traceId**是关联一次处理的线索，不是登录凭证，也不保证这次请求的完整链路已经保存。

当前运行日志经过这条路径：应用输出 → Docker 日志 → Alloy 采集 → Loki 存储 → Grafana 查询。应用默认按 Compose 配置输出 ECS JSON；可选的 Alloy、Loki、Grafana 没启动时，容器日志仍然存在，但集中检索尚不可用。
