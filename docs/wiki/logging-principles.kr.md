# 1. 통합 로그 수집: 무엇을 찾을지 먼저 정하기

사용자가 “조금 전 저장에 실패했어요”라고 말하면 발생 시간, 서비스, 처리가 멈춘 지점을 알아야 합니다. 로그는 처리 과정에서 발생한 사건의 기록입니다. 마이크로서비스에서는 여러 컨테이너에 흩어지므로, 한곳으로 수집하면 컨테이너마다 열어 보지 않고 검색할 수 있습니다.

## 세 기록은 서로 다른 질문에 답한다

| 기록 | 주로 답하는 질문 | 이 프로젝트의 확인 위치 |
|---|---|---|
| 실행 로그 | 서비스가 왜 실패했고 요청이 어디까지 진행됐는가 | Docker 로그, 수집 활성화 시 Grafana에서 Loki 검색 |
| 작업 로그 | 누가 어떤 업무 작업을 했고 결과는 무엇인가 | 내 작업대 → 운영 모니터링 → 작업 로그 |
| 보안 감사 | 로그인, 거부, 보안 설정 변경이 어떻게 발생했는가 | 시스템 관리의 감사 로그, 로그인 기록, 인가 기록 |

공급업체 수정 실패를 조사한다면 실행 로그로 예외를, 작업 로그로 실행자와 작업을, 로그인 기록으로 신원 확인 과정을 찾습니다. 서로 대신할 수 없습니다. 작업 로그가 비어 있어도 요청이 없었다고 단정할 수 없습니다.

## 먼저 알아둘 용어

**구조화 로그**는 시간, 수준, 서비스, 메시지를 필드로 나눕니다. **수집기**는 기록을 옮기고, **저장소**는 보관과 검색을, **조회 화면**은 표시를 담당합니다. **traceId**는 상관관계의 단서이지 로그인 자격 증명이나 전체 트레이스 저장의 증거가 아닙니다.

실행 로그 경로는 앱 출력 → Docker 로그 → Alloy → Loki → Grafana입니다. 앱 Compose 설정은 ECS JSON을 기본으로 사용합니다. 선택 기능인 Alloy, Loki, Grafana가 실행되지 않아도 컨테이너 로그는 남을 수 있지만 통합 검색은 사용할 수 없습니다.
