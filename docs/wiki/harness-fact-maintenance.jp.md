# 事実の維持と失効：文書をコードに追従させる

Harness における「事実」は飾りの説明ではなく、実行と検証の両方が依存する現在の情報です。事実が古くなると、モデルは古い規則でコードを生成し、検査は誤った前提で通過します。本稿は、Omni-Stack が現在どのように事実を記録、更新、失効させているか、そしてどこに人の判断が残るかを説明します。

## 事実に最低限必要な四つ

「購買依頼は `proc_*` テーブルを使い、テナントはインターセプタが処理する」を例にすると、保守可能な記録には次が必要です。

1. **適用範囲**：どのモジュール、テーブル、身元に適用されるか。
2. **現在の振る舞い**：あるべき論ではなく、コードが実際にどう動くか。
3. **証拠入口**：ソース、マイグレーション、テスト、実行記録の位置。
4. **失効条件**：テーブル名、遮断範囲、権限コードの変更など、いつ事実でなくなるか。

どれか欠けると読者は推測するしかありません。特に失効条件は重要で、次の変更時に誰が事実を更新すべきかを決めます。

## 事実の三つの媒体

| 媒体 | 適する内容 | 維持方法 |
|---|---|---|
| 事実文書 | アーキテクチャ境界、API 契約、モジュール規則 | コード変更時に同期し、適用する品質ゲートを実行 |
| ドキュメントマニフェスト | ソース、翻訳、審査状態、証拠 | ソース変更で摘要更新と審査待ちを発生 |
| テストと検査 | 自動判定できる制約 | 失敗をフィードバックとし、記憶に頼らない |

三つは互換できません。文書が良くてもマニフェスト状態が真実とは限らず、`synchronized` でも本文がソースと一致するとは限らず、テスト通過もすべての事実の網羅を意味しません。

## ソース変更後に起きること

`refresh-source-digests.mjs` は中国語事実源の SHA-256 を計算し、`docs/docs-manifest.yaml` の記録と比較します。ずれがあれば次を行います。

1. ソース摘要を更新する。
2. 影響する翻訳を `present-unverified` に戻す。
3. 古いレビュー済みソース摘要を削除し、履歴のレビュー記録は残す。
4. `docs-review-queue.mjs` にレビュー待ちを再生成させる。

つまり中国語本文の変更が、古い翻訳署名を黙って再利用することはありません。実例として、今回の変更で README と `docs/wiki/index.md` の編集が二つのソース摘要のずれを起こしました。更新後、紹介章の三翻訳は他の影響項目とともにレビュー待ちに入り、その時点のキューは 9 件待ち、129 件完了、3 件中国語のみを示しました（その後、章の追加で待ち件数はさらに変化しています）。どれも直接 `synchronized` にはしていません。

## ソース抜粋を検査する理由

原理記事は Java や TypeScript を引用します。コードを Markdown にコピーするだけでは、ソース変更を記事が知りません。`docs/scripts/source-excerpts.test.mjs` は `omni:source` マーカーのある原理ページを再帰的に見つけ、ローカルの抜粋をリポジトリの実ファイルと比較します。上流の抜粋については、`repository@commit` 形式の出典マーカーを検査します。この検査は上流の原文を取得・比較するものではなく、内容の照合は別途必要です。

次の場合に失敗します。

- 抜粋が一行改変された。
- ソースファイルが存在しない。
- 適用言語の版が欠けている。
- 上流抜粋に追跡可能な版がない。

失敗は「文書テストが厳しすぎる」のではありません。記事が古いコードを現在として示している合図です。マーカーを削除したり比較を緩めたりせず、抜粋を更新して結論を再確認します。

## 古い証拠が失効するとき

ファイルが残っていても、次は古い証拠を失効させます。

- 本文や翻訳が変わった：古いレビューは新しい文言を覆わない。
- ソースが変わった：引用、振る舞いの説明、スクリーンショットが不正確になる。
- 設定やポートが変わった：起動手順が一致しなくなる。
- 依存や版が上がった：ビルドコマンドや期待結果が変わる。
- 環境が変わった：古い実行記録は現在の環境を証明しない。

証拠を再利用できるかは、日付の近さではなく入力摘要の比較から判断します。古い受け入れ記録は当時を説明できますが、現在の手順の検証を代替できません。

## 維持の循環

完全な事実維持には次を含みます。

1. コードまたは本文を変更する。
2. 影響する事実文書を更新する。
3. ソース摘要を更新し、失効した翻訳を確認する。
4. リンク、内容、ビルド、影響する実行検査を行う。
5. 結果と未完了項目を記録する。
6. 指定レビューが必要なら待ちのままにし、署名を偽造しない。

手順 3 で多数の翻訳が失効しても、キューを片付けるために一括で同期済みにしないでください。キューは未完了のレビューを見えるままにするためのものです。

## 人の判断が残る部分

自動検査は摘要の不一致、抜粋の改変、リンク切れを見つけますが、次は判断できません。

- 新しい振る舞いが業務意図に合うか。
- 翻訳が自然で用語が一貫しているか。
- スクリーンショットが現在の画面を説明しているか。
- 提案を実施する価値があるか。

これらは人、または明示的に認可されたレビュー担当者が、実際の身元と証拠をマニフェストに記録して行います。ツールが代わりに署名することはできません。
