# 1. 从零认识定时任务：谁在每天准时做事

假设你希望每天提醒自己喝水，或者每隔一会儿把待发送消息交给消息队列。让人守着页面点击显然不合适。定时任务就是事先约好“做什么、何时做”，到了时间由程序执行。

但把功能改成定时运行，并不会自动解决失败、重复和权限问题。本章先讲这些直觉，再看当前工程使用的 XXL-JOB，最后对着真实网页学习操作。无需先读 Java 源码。

## 先区分三个问题

| 问题 | 由谁负责 | 可以怎样理解 |
|---|---|---|
| 什么时候开始 | 调度中心 | 值班室的时间表 |
| 把这次工作交给哪台服务 | 调度中心的路由策略与执行器注册 | 给在线工作人员派单 |
| 到底做了什么、是否成功 | 执行器中的业务处理器 | 工作人员真正完成工作并回报 |

执行器不是另一个独立的业务系统。本项目的执行器随各个业务服务运行；原生 XXL-JOB Admin 是统一的调度管理网页。服务能接到派单，不代表业务已经完成，必须继续看执行记录和业务结果。

## 什么叫“分布式”

一个服务可能部署多份，也可能有多个服务各自做不同工作。调度中心要知道哪些执行器在线，并按规则选择执行地址。分布式调度把这些安排集中管理，方便查看和恢复。

它不等于“每个任务都自动被分成很多份”。普通路由可以只选择一个地址；分片广播则可能让多个地址分别执行。需要拆分的数据、分片规则和重复保护，仍由业务设计。

## Cron 是一张时间表

Cron 用几个位置描述秒、分钟、小时和日期。先用页面的时间选择器理解“每天几点”或“每隔多久”，再核对预计执行时间；不要把五位的系统 Cron 与这里的带秒表达式混用。

还要确认时区、任务耗时和错过执行时间后的策略。每十秒安排一次、每次却耗时一分钟，就必须考虑排队、丢弃或覆盖等阻塞策略。更多触发次数不会让处理器自动变快。

## 为什么会重复，为什么要幂等

服务可能已经完成操作，但回报成功时网络断了。调度中心只看到“没有确认”，再次派单就可能重复执行。手动执行也可能与定时执行碰在一起。

幂等可以理解为：同一件事再交一次，不会重复产生本来只该发生一次的结果。例如按稳定业务编号检查是否已经处理，或用唯一约束与事务保护记录。调度锁、失败重试和“只选择一台机器”，都不能代替业务幂等。

## 本项目有两条任务轨道

系统任务随工程提供，例如操作日志归档、MQ 消息中继，由有权限的管理员维护。个人任务由用户在“我的工作台”里创建，例如提醒喝水，只能查看和操作自己当前租户下的任务。

两条轨道共用 XXL-JOB，但入口、归属和日志不同。不要在原生 Admin 中随意改个人任务来绕过工作台的归属校验。
