# Omni-Stack の実際の Harness

本稿は、リポジトリ内で指し示し実行できるものだけを扱います。能力の構想ではなく、業界概念を本プロジェクトの実装として書くものでもありません。判定は単純です。すべての記述がファイルまたは実際の検査にたどれる必要があります。

## 文脈：事実文書と入口

Omni-Stack は現在の振る舞いを会話ではなくリポジトリに書きます。

- ルート [AGENTS.md](../../AGENTS.md) の System Truth 表は、アーキテクチャ、API 契約、バックエンド／フロントエンドのパターン、コアフロー、業務モジュール文書を列挙します。Hard Constraints と Completion Checklist が実行境界を定めます。
- [アーキテクチャとエンジニアリング事実](../architecture.jp.md)、[API 契約](../api-contract.jp.md)、各モジュール文書が保守担当者の現在の基準です。
- [ソース入口索引](../reference/source-map.jp.md)がクラスやメソッドの位置を示し、ディレクトリの盲検索を減らします。
- [ドキュメントマニフェスト](../docs-manifest.yaml)が各文書のソース、翻訳、審査証拠、状態を記録します。

これらは「現在何か」に答え、「かつて何だったか」ではありません。過去の受け入れ記録は、現在の手順の検証を代替できません。

## ツール：実行できる行為

| 行為 | 入口 | 結果 |
|---|---|---|
| バックエンドビルド | `omni-backend/mvnw`（コンテナ内 JDK 25） | コンパイル、テスト、インストール |
| フロントエンドのビルドと検査 | `omni-frontend` の `npm run build`、`npm run lint` | 型、ビルド、ESLint |
| サービスと CRUD の生成 | `tools/omni-cli` | 新モジュール骨格または絞り込みプロジェクト |
| プリセット構造の検証 | CLI のプリセット生成と構造アサーション | モジュール、Compose、ゲートウェイ、シードの一致 |
| 文書検査 | `tools/omni-cli` の docs スクリプト | リンク、README、国際化内容、機密情報、スクリーンショット範囲 |
| サイトビルド | `docs` の `npm test`、`npm run build` | 文書テストと VitePress ビルド |

自動化は多ければ良いわけではありません。文書サイトのビルド成功はページが生成できただけで、翻訳が審査済みという意味ではありません。終了コードとその検査範囲は分けて記録する必要があります。

## 制約：リポジトリに書かれたハードルール

以下は `AGENTS.md` と事実文書に由来する現在の制約で、提案ではありません。

- コントローラは `R<T>` を返し、ページングは `R<PageResult<T>>` を返す。
- `@Autowired` のフィールド注入を使わず、サービスはインターフェースと実装に分ける。
- 書き込み操作は `resource:action` 権限コードを宣言し、権限シードとフロントエンド指令を同期する。
- Gateway 5.x は `spring.cloud.gateway.server.webflux` 接頭辞を使う。
- WebFlux サービスはリアクティブ Redis モジュールだけに依存する。
- データ権限インターセプタはページングより先に登録し、`DataScopeContext` は `finally` で消す。
- 四言語、テナント、権限、モジュール境界は各モジュール文書に従う。

制約は検査されて初めて意味を持ちます。リポジトリはテスト、構造アサーション、マニフェスト検査、レビューを通じて制約を検証へ接続し、文書だけに置きません。

## 検証：単点ではなく層

現在のリポジトリには少なくとも次の層があります。

1. **単体と構造**：バックエンドモジュールテスト、フロントエンドのナビゲーションテスト、プリセット残留とマトリクスのアサーション。
2. **ビルド**：Maven reactor、フロントエンドの `vue-tsc` + Vite、文書サイトビルド。
3. **文書の真実性**：`docs/scripts/source-excerpts.test.mjs` は原理ページのローカル抜粋をリポジトリの実ファイルと比較し、改変やファイル欠落を失敗させる。上流の抜粋は版の出典マーカーを検査するが、上流原文との内容照合を証明するものではない。
4. **内容品質**：リンク、README の責務、国際化内容、機密情報、スクリーンショット範囲を `docs-quality.mjs` のスコープで検査。
5. **実行と納品**：ローカル Docker のサービス健全性、実ログイン、画面操作、生成物自身のビルドと絞り込み。

各層は自分の範囲だけを証明します。単体テストの通過は実ログインの可用性を、サイトビルドの通過は翻訳レビューを、生成構造の正しさは生成物の独立起動を証明しません。

## フィードバックと断点：失効を見えるようにする

三つの仕組みが変化を見える状態にします。

- **ソース摘要の更新**：`refresh-source-digests.mjs` が中国語事実源の SHA-256 のずれを検出し、影響する翻訳を `present-unverified` に戻し、古いレビュー摘要を削除します。古い署名が有効なふりを続けることはありません。
- **ドキュメントマニフェスト**：`docs/docs-manifest.yaml` が翻訳状態、審査証拠、公開方針を記録し、`docs-review-queue.mjs` がレビュー待ちを作ります。
- **ソース抜粋検査**：記事中の Java/TypeScript 抜粋が現在のソースと一致することを要求し、「記事は残り、コードは動いた」を防ぎます。

これらの仕組みは読める対象だけを覆います。実画面のスクリーンショット、外部認可フロー、実行時挙動は別の証拠が必要です。証拠がない場合は文書状態で代用せず、未完了リストに記録します。

## AI 資産：規範ソースと派生入口

[ai/README.md](../../ai/README.jp.md)は、`ai/` が規範ソースであり、ルート `AGENTS.md` とエンジニアリング事実が制約を定めると説明します。`ai/skills`、`ai/prompts`、`ai/knowledge`、`ai/adapters` がそれぞれスキル、プロンプト雛形、出典のあるプロジェクト経験、ツール発見入口を担います。adapter はユーザー変更を保護し、差分があれば上書きを拒否します。

したがって AI 資産も Harness の一部です。出典、版、ライセンス、失効条件を持ち、散在するプロンプトではありません。リポジトリは個人アカウント、トークン、記憶を含まず、自動ネット研究基盤も提供しません。

## まだ実装していないこと

- 常駐する自律代理ランタイムはなく、モデルが自動でコミット、公開、本番操作する経路もない。
- 外部資料を自動取得する研究基盤はない。外部ソースは人が開き、日付を記録し、支持範囲を判断する必要がある。
- 「ビルド成功」を「機能検証完了」と同一視する仕組みはない。両者は別に記録する。
- すべてのページのスクリーンショットや実外部認可の証拠はない。不足は未完了リストに残す。

境界を書くことが、Harness を保守可能にします。次は[事実の維持と失効](harness-fact-maintenance.jp.md)、または[二次開発の小さなタスク](harness-secondary-development.jp.md)へ。
