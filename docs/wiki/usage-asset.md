# 资产全功能图文教程：把一件资产从入库管到退出使用

一台新电脑到货后，谁来登记、交给谁、谁来确认？借给别人、送去维修、最后报废，又分别该点哪里？本篇按这些日常问题介绍资产模块。先认清“东西现在归谁用”，再处理审批和实物交接，就不容易把几个步骤混在一起。

本文的图片来自本地专用演示账号和真实操作。图片展示的是不同操作时刻；丢弃和报废使用两张独立样例卡，不是一张卡同时处于两种终态。图中的英文名称、账号名和部门编号是演示数据，使用时请换成你有权处理的对象。

## 一、先打开模块，认清自己的身份

在首页打开“我的工作台”，会进入新的浏览器页签。在工作台的应用目录或“应用”弹窗中选择“资产管理”，再打开独立的资产页签。已经进入资产模块后，左侧和右上角搜索只围绕当前模块；要换应用，请切回原来的工作台页签。

不同身份能做的事不同：

| 身份 | 主要看什么、做什么 |
| --- | --- |
| 资产管理员 | 查看本租户台账，登记资产，分配、送修，发起和完成调拨或处置 |
| 资产经理 | 在获授权的部门范围内管理资产；是否能审批某笔申请，以工作台实际收到的待办为准 |
| 资产使用人 | 查看自己名下的资产，确认领用和退还；不能代替管理员维护全体资产 |

有资产经理角色，不代表能处理所有人的审批任务。反过来，拥有一条待办，也不等于获得整个资产模块的管理权限。遇到没有菜单或没有按钮，先核对身份和状态。

## 二、用概览找到问题，再去台账看明细

进入“资产概览”，先看各状态数量，再按状态、品类、部门或位置切换分布。它帮助你发现“待领用太多”“维修中的设备还没收回”等问题。

图中的数字是取证时刻的真实数据。处理完一笔业务后可以刷新；不要把概览数字当成某一件资产已经交接的凭证，具体结果仍需到台账确认。

![资产概览：先看数量与分布，再决定查看哪些资产](../images/zh-CN/asset-overview.png)

## 三、在台账里找资产、查来源、看历史

打开“资产台账”，按名称或资产编号搜索；需要时再选状态、管理部门、位置等条件。点击“搜索”应用条件，“重置”清掉条件。换页或调整每页条数，可查看其余记录。

列表较宽时，可以横向滚动查看右侧状态和操作。图中有些左侧列会因此离开视口；搜索框中的编号和详情页仍可帮助你确认正在处理哪一件资产。

![资产台账：关键词、筛选、分页和右侧操作](../images/zh-CN/asset-ledger.png)

点击“详情”，在右侧抽屉查看名称、原值、位置、当前使用人和当前部门，再看下面的变更历史。图中的手工样例最初没有使用人，金额为 125.50 CNY；不要把“管理员”误当成“当前使用人”。

![手工资产详情：基本资料、使用关系与变更历史](../images/zh-CN/asset-detail.png)

历史中会同时保留发起和恢复等记录。判断现在能做什么，先看当前状态；追查怎么走到这里，再按时间看历史。历史较长时向下滚动，截图只展示当时可见的部分。切换界面语言不会改写已经保存的业务说明。

## 四、采购到货后，资产卡怎样出现

采购收货单完成质检并确认后，符合资产管理条件的实物会自动生成资产卡。前提是质检合格、物料纳入资产管理，并且资产数量是正整数。例如两台同型号设备，可以对应两张独立资产卡，之后分别分配和维修。

到台账打开详情，核对采购订单、收货单和来源信息，再与实物对照。本图沿用采购教程中已实际核对的来源卡：它与后文的手工演示卡不同。

![采购来源资产：详情保留真实订单、收货来源和金额](../images/zh-CN/procurement-assets.png)

如果收货已经确认却没找到卡片，先核对搜索条件，再回到收货单检查质检结果、资产管理标记和数量。不要为同一批实物反复手工建卡；无法确认时保留单号交给管理员排查。

## 五、没有采购来源的资产，怎样手动入库

已有设备补录等场景可以使用“手动入库”。在台账右上角打开表单，填写名称、品类、规格、品牌型号、采购日期、原值、币种和位置，再选择负责的管理员，核对带出的管理部门。有保修信息时，可以补充保修截止日期和预计使用年限。

需要关联供应商时，在供应商框中输入名称并选择有权使用的搜索结果，旁边的供应商名称会自动带出。它用于保留当时选定的名称，不应手工冒写；没有合适结果时先核对供应商资料与权限。

金额按页面提示填写，例如 125.50；不要在金额框里附带币种或说明文字。管理员应从合法选项中选择，部门与该用户一致，不要照抄演示编号。

![手动入库：填写资产资料与金额](../images/zh-CN/asset-create-dialog.png)

表单较长时向下滚动，检查备注、管理归属和底部按钮。确认无误后保存；系统生成资产编号，初始状态是“在库”。取消表单会放弃本次填写，不会新增资产。

![手动入库表单下半部：核对归属后保存或取消](../images/zh-CN/asset-create-footer.png)

手动建卡不会补出采购订单或收货单。没有来源和已经有采购来源，是两类不同的资产记录，不能用备注把一张手工卡冒充采购生成的卡。

## 六、编辑、删除和版本冲突

对可编辑的在库资产点击“编辑”，修改名称、品牌型号或备注等资料。编辑表单没有单独改位置的输入框，不要把“改资料”当成实物迁移。提交前再核对这是不是目标资产；如果别人已经修改过，页面会提示冲突，这时刷新后重新检查，不要连续重复提交。

![编辑资产：查看当前资料后再修改](../images/zh-CN/asset-edit-dialog.png)

编辑表单也有下半部分，管理归属和底部操作需要滚动查看。修改负责的管理员，不等于把资产交给一个新的使用人；实际交付应走后面的分配或调拨。

![编辑表单下半部：管理归属与底部操作](../images/zh-CN/asset-edit-footer.png)

“删除”用于清理尚未投入使用、没有使用关系和活动业务的手工在库记录。确认框出现时先核对名称或编号，确认后再刷新列表。采购来源卡，以及已经发生业务的资产，不能用删除代替退出管理；实物要退出使用，应按实际情况走处置。

## 七、管理员分配，不等于本人已经领用

在台账找到可分配的在库资产，点击“分配”。选择使用人，核对其所属部门，补充必要备注。目标使用人必须是可用账号，并属于所选部门；选项会受你的授权范围限制。

![分配表单：选择目标使用人，核对自动带出的部门](../images/zh-CN/asset-allocate-dialog.png)

分配成功后，资产进入“待领用”，当前使用人和部门已登记。此时管理员已经安排了接收人，但接收人还没有确认实物到手。下图展示同一演示资产再次分配后的真实待领用状态。

![分配后：台账显示待领用，还不是使用中](../images/zh-CN/asset-allocated.png)

如果你想把正在使用的资产交给另一个人，不要再次点击分配；应先归还后重新分配，或按后文的调拨流程办理。

## 八、使用人确认领用，或直接退还未领取的资产

被分配的人进入资产台账的“我的资产”，找到待领用记录，点击“确认领用”。在确认框中核对编号，确认实物、本人和记录一致后提交。管理员不能代替另一个人确认。

![本人确认领用：核对资产后再确认](../images/zh-CN/asset-accept-confirm.png)

确认成功后，刷新“我的资产”，状态变为“使用中”。图中账号是这件样例资产的实际使用人；另一个同部门账号不会因为部门相同就拥有同一件资产。

![我的资产：本人确认后显示使用中](../images/zh-CN/asset-my-in-use.png)

如果尚未领取就决定退回，可以对待领用记录点击“退还”。它不要求先确认领用再归还；请先核对实物确实没有留在自己手中。

![未确认领用也能退还：这是单独的归还路径](../images/zh-CN/asset-return-before-accept-confirm.png)

## 九、使用中的资产怎样归还

使用人完成实物归还后，在“我的资产”找到使用中的记录，点击“退还”，核对编号并确认。此操作只针对当前登录人名下符合状态的资产。

![使用后归还：先完成实物交回，再确认退还](../images/zh-CN/asset-return-confirm.png)

归还成功后，资产回到“在库”，不再记在本人名下，所以它会从“我的资产”中消失。空列表不一定是丢数据；可以请有权限的管理员到台账查同一编号。

![归还后：当前账号的我的资产列表不再显示这件资产](../images/zh-CN/asset-my-returned.png)

管理员打开详情，可以看到当前使用关系已清空，历史里保留分配、领用和退还过程。采购来源资产的来源信息也会保留。

![归还历史：当前在库，过去发生的业务仍可追查](../images/zh-CN/asset-return-history.png)

## 十、送修和修复归还，不改变使用归属

管理员对使用中的资产点击“送修”，在确认框中核对资产。送修后进入“维修中”，这段时间不能把它当成在库设备再次分配，也不能同时发起调拨或处置。

![送修前确认：核对资产和当前状态](../images/zh-CN/asset-maintenance-confirm.png)

![维修期间：台账显示维修中，等待修复归还](../images/zh-CN/asset-maintenance.png)

维修结束、实物交还后，管理员点击“修复归还”并确认。资产恢复“使用中”，原使用人和部门保留。这里的“归还”是维修结束回到原使用状态，不是使用人退还到库存。

![修复归还确认：恢复原使用状态，不重新分配使用人](../images/zh-CN/asset-maintenance-complete-confirm.png)

## 十一、调拨先发起申请，再由实际审批人处理

打开“资产调拨”，点击“发起调拨”。选择你有权处理、当前可用且未被其他申请占用的资产，再选目标使用人、核对目标部门，填写目标位置和原因。可选资产不限于在库，也可能包括待领用或使用中的资产，以页面实际可选项为准。

![调拨表单：资产、目标使用人、部门、位置和原因](../images/zh-CN/asset-transfer-form.png)

图中的填写表单只是提交前的预览；只有实际提交后，才会出现申请编号。发起后打开详情，核对原使用人与目标使用人、原位置与目标位置，确保没有选错。

![待审批的调拨：原使用关系和目标提案分开显示](../images/zh-CN/asset-transfer-pending-detail.png)

审批人切回“我的工作台”页签，在“待我审批”中打开实际收到的任务。先读原使用关系和调拨原因，再选择通过或驳回，填写意见并确认。下图展示实际审批人的驳回选择；打开弹窗本身不表示审批已经提交。

![真实调拨待办：核对提案，选择通过或驳回](../images/zh-CN/asset-transfer-approval.png)

申请处理中，资产会显示“调拨中”，原使用关系还没有按提案切换。这是为了避免同一件资产被两笔业务同时处理；不要另起一笔申请来绕过等待。

## 十二、调拨通过以后，还要完成实物交接

审批通过后，管理员回到资产页签的“资产调拨”，找到原申请，核对结果，再完成实际交接。确认接收人和位置无误，才点击“完成交接”并确认。

![完成交接确认：审批通过之后才执行的实物步骤](../images/zh-CN/asset-transfer-complete-confirm.png)

完成后，申请显示“已完成”，资产恢复使用状态，当前使用人、部门和位置按这笔调拨的目标更新。原负责管理资产的管理员，与接收实物的人，是两个不同概念。

![调拨完成：申请终态与实物交接结果已经落地](../images/zh-CN/asset-transfer-completed.png)

如果审批被驳回，目标提案不生效，资产恢复申请之前的状态。图中是使用中的资产被驳回后，仍保留原使用人、部门和位置；若申请前是其他可用状态，也应按原状态核对。

![调拨驳回后的资产：原使用关系保留，历史记录恢复原因](../images/zh-CN/asset-transfer-rejected.png)

## 十三、处置要分清丢弃、报废和最终确认

打开“资产处置”，点击“发起处置”。选择可处理的资产，选择丢弃或报废，填写原因；按实际情况填写残值和处置方式。先核对实物，再核对所选类型，不能只看按钮颜色作判断。

![处置表单：选择类型、核对资产，填写原因和残值](../images/zh-CN/asset-disposal-form.png)

提交后资产进入“待处置”，审批人在工作台实际收到的待办中检查类型、原状态、残值、处置方式和原因，再通过或驳回。示例待办中的原状态和业务说明是保存下来的真实内容。

![处置待办：审批前核对资产、类型、残值和原因](../images/zh-CN/asset-disposal-approval.png)

审批通过之后，资产还没有完成退出使用。管理员应先确认实物已按约定回收、销毁或移交，再回到原处置申请点击“完成处置”。

![最终处置确认：审批通过后仍需要核对实物](../images/zh-CN/asset-disposal-complete-confirm.png)

完成“丢弃”的样例卡进入“已丢弃”。图中的卡与下方报废卡是两件不同的实物样例；这两个终态都不能用退还或重新分配恢复。

![丢弃完成：独立样例卡进入已丢弃](../images/zh-CN/asset-disposal-completed.png)

![报废完成：另一张样例卡进入已报废](../images/zh-CN/asset-disposal-scrapped.png)

如果审批驳回，处置不会生效，资产恢复申请前状态，原使用关系保留。不要把“处置申请被驳回”误解成“实物已经处置后又恢复”。

![处置驳回：实物处置没有发生，资产恢复原使用关系](../images/zh-CN/asset-disposal-rejected.png)

## 十四、提交后没有明确结果，怎样安全重试

如果提示审批启动结果待确认，先搜索原申请，打开详情并刷新。它可能仍显示“待审批”，但还没有明确的流程实例。不要再次新建同一业务，也不要直接认定审批已经失败。

管理员先处理缺失的流程前置，例如实际审批候选人的组织范围。确认前置恢复后，在原申请行点击“重试”，核对申请编号并确认。重试沿用原申请，不是复制一笔新业务。

![调拨启动待确认：对原申请预览重试确认框](../images/zh-CN/asset-transfer-retry-confirm.png)

![处置启动待确认：同样保留原申请后重试](../images/zh-CN/asset-disposal-retry-confirm.png)

图中的确认框只展示即将执行的操作；判断重试是否成功，还要刷新详情，查看流程实例及审批人的真实待办。审批结果出来后，再按通过或驳回的路径核对资产。

只有页面明确显示“启动失败”，并提供“取消”时，才可核对原申请后使用本地取消。结果待确认时不允许这样取消；没有出现取消按钮，也不要用重复发起来代替它。本章的重试图片展示的是结果待确认，不能把它当成明确启动失败的截图。

## 十五、流程取消与申请本地取消，要分开理解

已经启动的审批流程若被合法终止，调拨或处置申请会收到取消结果，资产恢复到申请前状态。下面两图分别展示真实流程取消后的资产和最新历史，原使用人、部门和位置都保留下来。

当前页面没有终止已启动流程的按钮，因此这里展示取消后的结果，不提供一个并不存在的点击路径。它也不是上一节“明确启动失败后本地取消”的示例。

![调拨流程取消后的结果：资产恢复原使用关系](../images/zh-CN/asset-transfer-cancelled.png)

![处置流程取消后的结果：原使用关系保留，最新历史说明取消](../images/zh-CN/asset-disposal-cancelled.png)

无论驳回还是合法取消，都应回到原申请和资产详情核对最终结果。审批通过尚未交接的申请仍占用资产，不能因为已经通过就同时再发起一笔业务。

## 十六、看不到数据、没有按钮，先按这个顺序检查

先核对你在哪个浏览器页签、当前账号是谁，再检查筛选条件和资产状态，最后核对角色与部门范围。不要把所有空列表都当成系统故障。

下图是另一个部门的演示经理：角色存在，但不在这组资产的管理范围内，所以看不到记录。它不应通过改搜索参数看到其他部门的资产。

![部门范围外的空列表：有角色也不代表能查看这组资产](../images/zh-CN/asset-scope-empty.png)

使用人进入管理功能时会受到权限限制。应该回到“我的资产”处理本人记录，而不是给自己补成管理员来完成日常领用。

![管理功能拒绝访问：使用人身份不具备管理权限](../images/zh-CN/asset-management-forbidden.png)

| 退还以后记录不见了 | 是否已经回到在库 | 请管理员搜索原编号，看当前状态和历史 |
| 没有分配、编辑或删除按钮 | 当前身份、资产状态、采购来源和已有业务 | 不重复提交，改用当前允许的业务路径 |
| 没有审批待办 | 是否实际指派给当前账号，审批前置是否完整 | 由有权管理员检查候选人与组织范围 |
| 审批通过，资产还在调拨中或待处置 | 实物交接或处置是否已经确认 | 核对实物后，在原申请完成最后一步 |
| 提示资产已被其他申请占用 | 调拨或处置列表中的原申请是否结束 | 先处理原申请，不同时发起两类业务 |
| 提交后结果待确认 | 原申请是否已经存在，详情是否有流程实例 | 恢复前置后重试原申请，不重新建单 |
| 提示记录已被修改 | 其他人是否已经操作或页面停留太久 | 刷新，核对现状后再决定是否操作 |
| 列表或按钮拒绝访问 | 是否超出当前角色或部门范围 | 切换到本人有权使用的入口，由有权人员处理管理业务 |

对有审批的调拨和处置，至少核对两处：原申请的最终状态，以及资产卡上的当前状态和使用关系。这样才知道审批、实物和系统记录是否已经一致。
