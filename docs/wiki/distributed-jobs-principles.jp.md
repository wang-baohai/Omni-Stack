# 1. 定期実行を基礎から理解する：時間になったら誰が働くのか

毎日決まった時刻に水分補給を知らせたり、送信待ちのメッセージを一定間隔でキューへ渡したりする場面を考えてください。人が画面を開いてボタンを押し続ける代わりに、「何を、いつ行うか」を登録してプログラムに実行させるのが定期ジョブです。

ただし、定期実行に変えるだけでは失敗、重複、権限の問題は解決しません。本章では身近な考え方から始め、現在の XXL-JOB の仕組みを学び、実際の画面で操作を確認します。最初から Java を読む必要はありません。

## 三つの問いを分ける

| 問い | 担当 | 身近なたとえ |
|---|---|---|
| いつ始めるか | スケジューリングセンター | 時間割を持つ当直室 |
| どのサービスの実行先へ渡すか | ルーティングと実行器の登録 | 空いている担当者への割り当て |
| 何が行われ、成功したか | 実行器内の業務ハンドラー | 実作業と結果報告 |

実行器は別の独立した業務システムではありません。本プロジェクトでは各業務サービス内で動作し、XXL-JOB Admin が共通の管理画面になります。依頼を受け付けたことと業務が完了したことは別なので、実行記録と業務結果まで確認します。

## 「分散」とは何か

一つのサービスが複数台で動くことも、複数のサービスが別々の仕事をすることもあります。センターは利用可能な実行器を把握し、方針に従って送信先を選びます。集約管理によって状況確認と復旧を行いやすくします。

すべてのジョブが自動的に分割される意味ではありません。通常のルーティングでは一つの実行先を選ぶ場合があり、分割ブロードキャストでは複数先が実行する場合があります。データの分け方と重複防止は業務側の設計です。

## Cron は時間割

Cron は秒、分、時、日付などの位置で実行時刻を表します。まず画面の設定で「毎日の何時」「どの間隔」を理解し、実行予定時刻を確認します。ここで使う秒付きの式と、OS の五項目の式を混同しないでください。

タイムゾーン、処理時間、実行時刻を逃した場合の方針も確認します。十秒間隔なのに処理に一分かかるなら、待ち行列、後続の破棄、先行処理の置き換えなどの同時実行時の待機方針が必要です。起動回数を増やしても処理自体は速くなりません。

## 重複が起きる理由と冪等性

処理が完了しても、成功を返す通信が切れることがあります。センターには確認が届かず、再び割り当てると処理が重複するかもしれません。手動実行と定期実行が重なる場合もあります。

冪等性とは、同じ仕事を再度受けても、一度だけであるべき結果を増やさないことです。安定した業務番号による確認、ユニーク制約、適切なトランザクションなどで守ります。スケジューリング用のロック、再試行、送信先を一台にする設定だけでは代替できません。

## 本プロジェクトの二つの系統

システムジョブはログのアーカイブや MQ 中継など、プロジェクトに含まれる保守処理で、権限を持つ管理者が扱います。個人ジョブは水分補給の通知など、ユーザーが「マイワークスペース」で作り、現在のテナントと作成者に属する仕事です。

同じ XXL-JOB を使っても入口、帰属、ログは異なります。個人ジョブをネイティブ Admin で変更して、ワークスペースの帰属検査を迂回しないでください。
