# Omni-Stack의 실제 Harness

이 글은 저장소에서 가리키고 실행할 수 있는 것만 다룹니다. 능력의 청사진이 아니며 업계 개념을 이 프로젝트의 구현으로 쓰지도 않습니다. 판단은 단순합니다. 모든 서술은 파일이나 실제 검사로 이어져야 합니다.

## 문맥: 사실 문서와 진입점

Omni-Stack은 현재 동작을 대화가 아니라 저장소에 씁니다.

- 루트 [AGENTS.md](../../AGENTS.md)의 System Truth 표는 아키텍처, API 계약, 백엔드/프런트엔드 패턴, 핵심 흐름, 업무 모듈 문서를 나열합니다. Hard Constraints와 Completion Checklist가 실행 경계를 정합니다.
- [아키텍처와 엔지니어링 사실](../architecture.kr.md), [API 계약](../api-contract.kr.md), 각 모듈 문서가 유지보수자의 현재 기준입니다.
- [소스 진입점 색인](../reference/source-map.kr.md)이 클래스와 메서드 위치를 알려 주어 디렉터리 맹검색을 줄입니다.
- [문서 매니페스트](../docs-manifest.yaml)가 각 문서의 소스, 번역, 검토 증거, 상태를 기록합니다.

이들은 "지금 무엇인가"에 답하며 "한때 무엇이었나"가 아닙니다. 과거 수용 기록은 현재 단계의 검증을 대체할 수 없습니다.

## 도구: 실행할 수 있는 행위

| 행위 | 진입점 | 결과 |
|---|---|---|
| 백엔드 빌드 | `omni-backend/mvnw`(컨테이너 내 JDK 25) | 컴파일, 테스트, 설치 |
| 프런트엔드 빌드와 검사 | `omni-frontend`의 `npm run build`, `npm run lint` | 타입, 빌드, ESLint |
| 서비스와 CRUD 생성 | `tools/omni-cli` | 새 모듈 골격 또는 축소 프로젝트 |
| 프리셋 구조 검증 | CLI 프리셋 생성과 구조 단언 | 모듈, Compose, 게이트웨이, 시드 일치 |
| 문서 검사 | `tools/omni-cli`의 docs 스크립트 | 링크, README, 국제화 내용, 민감 정보, 스크린샷 범위 |
| 사이트 빌드 | `docs`의 `npm test`, `npm run build` | 문서 테스트와 VitePress 빌드 |

자동화가 많다고 좋은 것은 아닙니다. 문서 사이트 빌드 성공은 페이지 생성만 뜻하며 번역 검토 완료를 뜻하지 않습니다. 종료 코드와 그것이 덮는 범위는 따로 기록해야 합니다.

## 제약: 저장소에 적힌 하드 규칙

다음은 `AGENTS.md`와 사실 문서에서 온 현재 제약이며 제안이 아닙니다.

- 컨트롤러는 `R<T>`를 반환하고 페이지네이션은 `R<PageResult<T>>`를 반환합니다.
- `@Autowired` 필드 주입을 쓰지 않고 서비스는 인터페이스와 구현으로 나눕니다.
- 쓰기 작업은 `resource:action` 권한 코드를 선언하고 권한 시드와 프런트엔드 지시자를 동기화합니다.
- Gateway 5.x는 `spring.cloud.gateway.server.webflux` 접두사를 씁니다.
- WebFlux 서비스는 리액티브 Redis 모듈에만 의존합니다.
- 데이터 권한 인터셉터는 페이지네이션보다 먼저 등록하고 `DataScopeContext`는 `finally`에서 지웁니다.
- 4개 언어, 테넌트, 권한, 모듈 경계는 각 모듈 문서를 따릅니다.

제약은 검사될 때만 의미가 있습니다. 저장소는 테스트, 구조 단언, 매니페스트 검사, 리뷰를 통해 제약을 검증에 연결하며 문서에만 두지 않습니다.

## 검증: 단일 지점이 아닌 계층

현재 저장소에는 최소한 다음 계층이 있습니다.

1. **단위와 구조**: 백엔드 모듈 테스트, 프런트엔드 내비게이션 테스트, 프리셋 잔여와 매트릭스 단언.
2. **빌드**: Maven reactor, 프런트엔드 `vue-tsc` + Vite, 문서 사이트 빌드.
3. **문서 진실성**: `docs/scripts/source-excerpts.test.mjs`는 원리 페이지의 로컬 발췌를 저장소의 실제 파일과 비교하고 변조나 파일 누락을 실패시킵니다. 상류 발췌는 버전 출처 표시를 검사하지만, 이 검사만으로 상류 원문과 내용을 대조했다고 할 수는 없습니다.
4. **내용 품질**: 링크, README 책임, 국제화 내용, 민감 정보, 스크린샷 범위를 `docs-quality.mjs` 스코프로 검사합니다.
5. **실행과 납품**: 로컬 Docker의 서비스 상태, 실제 로그인, 화면 조작, 생성물 자체 빌드와 축소.

각 계층은 자기 범위만 증명합니다. 단위 테스트 통과는 실제 로그인 가능성을, 사이트 빌드는 번역 검토를, 올바른 생성 구조는 생성물의 독립 기동을 증명하지 않습니다.

## 피드백과 체크포인트: 무효화를 보이게 하기

세 가지 장치가 변화를 보이는 상태로 만듭니다.

- **소스 다이제스트 갱신**: `refresh-source-digests.mjs`가 중국어 사실 소스의 SHA-256 차이를 감지해 영향을 받는 번역을 `present-unverified`로 되돌리고 오래된 검토 다이제스트를 삭제합니다. 오래된 서명이 유효한 척 계속할 수 없습니다.
- **문서 매니페스트**: `docs/docs-manifest.yaml`이 번역 상태, 검토 증거, 공개 정책을 기록하고 `docs-review-queue.mjs`가 검토 대기를 만듭니다.
- **소스 발췌 검사**: 글의 Java/TypeScript 발췌가 현재 소스와 일치하도록 요구해 "글은 남고 코드는 움직였다"를 막습니다.

이 장치들은 읽을 수 있는 대상만 덮습니다. 실제 화면 스크린샷, 외부 인가 흐름, 실행 시 동작은 별도 증거가 필요합니다. 증거가 없으면 문서 상태로 대체하지 말고 미완료 목록에 기록합니다.

## AI 자산: 규범 소스와 파생 진입점

[ai/README.md](../../ai/README.kr.md)는 `ai/`가 규범 소스이며 루트 `AGENTS.md`와 엔지니어링 사실이 제약을 정의한다고 설명합니다. `ai/skills`, `ai/prompts`, `ai/knowledge`, `ai/adapters`가 각각 스킬, 프롬프트 템플릿, 출처가 있는 프로젝트 경험, 도구 발견 진입점을 담당합니다. adapter는 사용자 수정을 보호하고 차이가 있으면 덮어쓰기를 거부합니다.

따라서 AI 자산도 Harness의 일부입니다. 출처, 버전, 라이선스, 무효화 조건을 가지며 흩어진 프롬프트가 아닙니다. 저장소는 개인 계정, 토큰, 기억을 포함하지 않고 자동 웹 연구 플랫폼도 제공하지 않습니다.

## 아직 구현하지 않은 것

- 상주하는 자율 에이전트 런타임이 없고, 모델이 자동으로 커밋, 공개, 프로덕션 조작을 하는 경로도 없습니다.
- 외부 자료를 자동 수집하는 연구 플랫폼이 없습니다. 외부 소스는 사람이 열고 날짜를 기록하고 지지 범위를 판단해야 합니다.
- "빌드 성공"을 "기능 검증 완료"로 동일시하는 장치가 없습니다. 둘은 따로 기록합니다.
- 모든 페이지의 스크린샷이나 실제 외부 인가 증거는 없습니다. 부족분은 미완료 목록에 남습니다.

경계를 적는 것이 Harness를 유지보수 가능하게 합니다. 다음은 [사실 유지와 무효화](harness-fact-maintenance.kr.md), 또는 [2차 개발의 작은 작업](harness-secondary-development.kr.md)입니다.
