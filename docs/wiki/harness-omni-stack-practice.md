# Omni-Stack 的实际 Harness

本页只讲仓库里现在能指向、能运行的部分。它不是能力愿景，也不把行业概念写成本项目已实现。判断标准很简单：每条说法后面都应能找到一个文件或一次检查。

## 上下文：事实文档与入口

Omni-Stack 把当前行为写进仓库，而不是只放在对话里：

- 根 [AGENTS.md](../../AGENTS.md) 的 System Truth 表列出架构、API 契约、后端/前端模式、核心流程和业务模块文档；Hard Constraints 与 Completion Checklist 给出执行边界。
- [架构与工程事实](../architecture.md)、[API 契约](../api-contract.md)和各模块文档是维护者的当前基线。
- [源码入口索引](../reference/source-map.md)帮助定位类和方法，减少在目录里盲搜。
- [文档清单](../docs-manifest.yaml)记录每篇文档的源、译文、审校证据和状态。

这些文件解决的是“当前是什么”，不是“曾经是什么”。历史验收记录不能替代当前步骤的验证。

## 工具：能执行的动作

仓库提供的工具让模型的动作可以被执行和检查：

| 动作 | 入口 | 结果 |
|---|---|---|
| 后端构建 | `omni-backend/mvnw`（容器内提供 JDK 25） | 编译、测试、安装 |
| 前端构建与检查 | `omni-frontend` 的 `npm run build`、`npm run lint` | 类型、构建、ESLint |
| 生成服务与 CRUD | `tools/omni-cli` | 新模块骨架或裁剪工程 |
| 预设结构验证 | CLI 的预设生成与结构断言 | 模块、Compose、网关、种子矩阵一致 |
| 文档检查 | `tools/omni-cli` 的 docs 脚本 | 链接、README、国际化内容、敏感信息、截图覆盖 |
| 站点构建 | `docs` 的 `npm test`、`npm run build` | 文档测试与 VitePress 构建 |

工具不是越自动越好。比如文档站构建成功只说明页面能生成，不说明译文已审校；运行命令的退出码和它实际覆盖的范围必须分开记录。

## 约束：写在仓库里的硬规则

以下规则来自 `AGENTS.md` 和事实文档，属于当前约束而不是建议：

- 控制器统一返回 `R<T>`；分页返回 `R<PageResult<T>>`。
- 不使用 `@Autowired` 字段注入；服务层使用接口 + 实现。
- 写操作声明 `resource:action` 权限码，并同步权限种子和前端指令。
- 网关 5.x 使用 `spring.cloud.gateway.server.webflux` 前缀。
- WebFlux 服务只能依赖响应式 Redis 模块。
- 数据权限拦截器先于分页拦截器；`DataScopeContext` 必须在 `finally` 清理。
- 四语言、租户、权限和模块边界按各模块文档执行。

约束只有被检查才有意义。仓库通过测试、结构断言、清单校验和评审把这些规则连接到验证，而不是只写在文档里。

## 验证：分层而非单点

当前仓库至少包含这些验证层：

1. **单元与结构**：后端模块测试、前端导航测试、预设残留与矩阵断言。
2. **构建**：Maven reactor、前端 `vue-tsc` + Vite、文档站构建。
3. **文档真实性**：原理页的本地源码片段由 `docs/scripts/source-excerpts.test.mjs` 逐段比对仓库文件，本地片段篡改或缺源会失败；上游片段检查版本来源标记，不能据此声称已比对上游原文。
4. **内容质量**：链接、README 职责、国际化内容、敏感信息与截图覆盖由 `docs-quality.mjs` 分 scope 检查。
5. **运行与交付**：本机 Docker 中的服务健康、真实登录、页面操作，以及生成工程自身的构建和裁剪检查。

每一层只能证明自己的范围。单元测试通过不能推出真实登录可用；站点构建通过不能推出译文已复核；生成物结构正确不能推出生成物能独立启动。

## 反馈与断点：让事实失效可见

Omni-Stack 用三个机制把“变化”变成可见状态：

- **源摘要刷新**：`refresh-source-digests.mjs` 检测中文事实源的 SHA-256 漂移，把受影响译文置回 `present-unverified`，删除旧的已复核摘要。旧签核不会继续冒充有效。
- **文档清单**：`docs/docs-manifest.yaml` 记录译文状态、审校证据和发布策略；`docs-review-queue.mjs` 生成待复核清单。
- **源码片段检查**：文章里引用的 Java/TypeScript 片段必须与当前源码一致，避免“文章还在、代码已变”。

这些机制只覆盖它们能读到的对象。真实页面截图、外部授权流程和运行时行为仍需要单独取证；没有证据时应在未完成清单中登记，而不是用文档状态代替。

## AI 资产：规范源与派生入口

[ai/README.md](../../ai/README.md)说明 `ai/` 是规范源，根 `AGENTS.md` 与工程事实仍定义约束。`ai/skills`、`ai/prompts`、`ai/knowledge` 和 `ai/adapters` 分别承载技能、提示模板、有来源的项目经验和工具发现入口。adapter 会保护用户修改，检测到差异时拒绝覆盖。

这意味着 AI 资产本身也在 Harness 内：它们有来源、版本、许可和失效条件，不是散落的提示词。仓库不包含个人账号、令牌或记忆，也不提供自动联网研究平台。

## 当前没有实现什么

- 没有常驻的自主代理运行时，也没有让模型自动提交、发布或操作生产环境的通道。
- 没有自动获取外部资料的研究平台；外部来源仍需人工打开、记录日期并判断支持范围。
- 没有把“构建成功”自动等同于“功能验证完成”的机制；两者分别记录。
- 没有覆盖所有页面的截图或真实外部授权证据；缺口在未完成清单中保留。

把边界写清楚，Harness 才是可维护的。下一步是[事实维护与失效](harness-fact-maintenance.md)，或直接按[二次开发小任务](harness-secondary-development.md)走一遍。
