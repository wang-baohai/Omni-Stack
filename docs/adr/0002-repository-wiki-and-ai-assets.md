# ADR-0002：仓库 Wiki 与共享 AI 资产

- 状态：Accepted；实现与证据按实际质量门验收
- 日期：2026-10-09
- 适用起点：主干 `fc165e3`
- 依据：本次用户明确选择仓库文档与独立站点、四语言同步并复核、保留重要历史、集中项目实际使用的 AI 资产
- 关系：补充 [ADR-0001](0001-scaffold-upgrade-foundations.md)，不改变业务安全或迁移决定
- 后续替代：2026-10-13 的 [ADR-0003](0003-authorized-ai-translation-review.md) 替代第 4 条的仅真人复核要求；其余决定保留

## 背景

README 承载模块、端口、教程与图库，工程事实也混有教学和历史环境。已有清单、四语言指南、截图和质量门应被复用。原检查器要求 README 含完整模块事实；部分 synchronized 记录的 reviewer 为 Codex，不能证明真实人工复核。

## 决定

1. README 负责定位、能力、最短入口与导航；工程事实保留行为、不变量和源码/测试入口；Wiki 负责学习与操作。
2. Markdown 与清单是唯一正文源。采用 VitePress 1.6.4 稳定版，生成语言目录，不维护第二份平台 Wiki。文档站是独立 Docker project，端口为 4173。
3. 使用本地全文搜索，正文仍能由 GitHub/Gitee 直接阅读。站点源码链接可配置托管平台。
4. 四语言每次变更同步。真实人工签核绑定源、译文摘要；自动审批和 AI 审校不得签为人工。
5. `ai/` 为共享资产规范源。工具原生发现通过可重复、保护用户改动的适配流程实现，不复制全局插件缓存、凭据或个人记忆。
6. 保留 ADR、精选变更和重要验收/事故；普通过程留在 Git 历史或私有运行产物。

## 取舍与后果

原生 GitHub/Gitee Wiki 会增加第二份可编辑内容；单独复制一个全新 docs 系统会造成规则与图片漂移，因此不采用。VitePress 沿用 Node 技术栈；其语言路径投影使已有带语言后缀的 Markdown 无需大规模移动。Python 文档栈会增加独立工具链，当前没有足够收益。

文档构建锁定 Vite 6.4.3 覆盖旧传递版本，兼容性必须通过构建与浏览器验证；这项覆盖仅属于文档站，不升级业务前端。VitePress 的稳定版与预发行版分别见[官方版本入口](https://vuejs.github.io/vitepress/v1/)，站点路由和搜索依据[路由文档](https://vuejs.github.io/vitepress/v1/guide/routing)、[本地搜索](https://vuejs.github.io/vitepress/v1/reference/default-theme-search)。

严格语言门可能暂时失败，这是实际待人工复核状态。预览、内容检查和发布验收分别记录。预设生成器需要同时裁剪文档导航、引用和 AI 清单，防止生成物依赖已移除模块。

## 复审条件

站点构建不再支持所用稳定版本、仓库直接阅读受损、工具发现方式变化、语言政策或资产许可变化时，新增 ADR 说明替代关系。不能通过删除质量门隐去待验收事项。
