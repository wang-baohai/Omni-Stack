# システムジョブ、個人ジョブ、ジョブ種別拡張

調度は二つの経路を持ちます。コードで宣言するシステムジョブは運用管理し、個人ジョブは承認済み種別からユーザーが作成します。どちらも XXL-JOB を使いますが、所有権とライフサイクルが異なります。

## 1. システムジョブ

MQ relay、ログアーカイブ、補償スキャンなどは、次の二つの注釈を必須とします。

```java
@XxlJob("handlerName")
@SystemJobMeta(...)
```

どちらかがないと `SystemJobRegistry` に表示されません。画面では登録、開始/停止、即時実行を管理し、実装はコードのリリースで管理します。

## 2. 個人ジョブ

ワークスペースで種別、Cron、JSON Schema の動的パラメータを入力して作成します。保存後は一時停止、再開、編集、即時実行、ログ確認ができます。個人ジョブは RBAC ではなく `createBy` 所有権を使い、共通 `userJobExecuteHandler` が `typeCode` で処理器を選択します。

## 3. ジョブ種別

安定した `typeCode`、表示名、説明、パラメータ Schema、状態を定義します。`typeCode` は `UserJobHandler` Bean 名と完全一致する必要があります。文字列の `enum` は選択欄として表示し、API には安定値を送ります。

## 4. 種別追加

処理器実装、同名 Bean、パラメータ検証、種別と Schema 登録、`omni-base` ビルド、隔離 XXL-JOB での作成/即時実行、成功・失敗・停止・更新・削除を確認します。

## 5. 整合性

DB 登録と XXL-JOB 登録は両方成功する必要があります。失敗時は `UserJobServiceImpl.createJob()` が行を削除します。セッション Cookie はメモリのみで自動更新します。定期実行と即時実行が重なるため処理器は冪等にします。

## 6. トラブルシューティング

画面に種別がない場合は状態とコード、XXL-JOB にない場合は Admin と実行器、ルーティング失敗は Bean 名、結果がない場合はジョブログ、システム処理器がない場合は二重注釈と `omni-common-job` を確認します。

[スケジューリング文書](../scheduling.jp.md)も参照してください。
